# 评审输出格式

先读取本地实际文件和 diff，再编译、跑测试，最后按严重程度输出。

```markdown
# 评审：[题目名称]

## 当前状态
- 实现文件：
- 编译：通过 / 失败（命令与关键输出）
- 测试：通过 / 失败
- 结论：继续修改 / 可进入下一题

## 1. 阻塞性错误
- 文件:行号 — 触发输入 — 后果 — 原因 — 修改方向

## 2. 正确性问题
- ...

## 3. 边界条件问题
- ...

## 4. C++ 与生命周期问题
- ...

## 5. 复杂度和性能问题
- ...

## 6. 工程设计问题
- ...

## 7. 风格与可读性建议
- ...

## 下一步
[只写学员现在该做什么，不重写完整答案]
```

空级别写“无”。指出问题时必须包含：触发输入或状态、实际后果、原因、修改方向。
